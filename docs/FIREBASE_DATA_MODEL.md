# Smart Transit Firebase data model

## Firestore

`users/{uid}` is the private rider profile. It contains `displayName`, `email`, `phoneNumber`, timestamps, and `settings.smsFallbackEnabled`.

| Path | Purpose | Client access |
| --- | --- | --- |
| `users/{uid}/savedStops/{stopId}` | Named rider stops: `name`, `latitude`, `longitude`, optional `note` | owner CRUD |
| `users/{uid}/tripRequests/{requestId}` | Origin, destination, optional route, lifecycle status and timestamps | owner CRUD |
| `users/{uid}/notifications/{id}` | Rider-specific messages and `readAt` | owner read/update/delete; trusted server creates |
| `routes/{routeId}` | `name`, `stops`, `fareRwf`, `geometry`, timetable data, timestamps | authenticated read; dispatcher/admin CRUD |
| `buses/{busId}` | `routeId`, `vehicleId`, capacity, next stop, ETA, status, timestamps | authenticated read; dispatcher/admin CRUD |

All timestamps are Firestore server timestamps. IDs are generated by Firestore, not user input.

## Realtime Database

`busLocations/{busId}` holds only high-frequency live data: `latitude`, `longitude`, `updatedAt` (epoch milliseconds). Authenticated riders can read it; only the assigned driver (`driverBusId` custom claim) or staff can write it.

## Setup and deploy

1. Run `flutterfire configure` from the project root. It creates `lib/firebase_options.dart` and platform Firebase files; do not hand-copy production credentials.
2. Enable Email/Password in Firebase Authentication.
3. Set `admin`, `dispatcher`, or `driverBusId` custom claims only from a trusted Admin SDK environment.
4. Deploy: `firebase deploy --only firestore:rules,firestore:indexes,database`.

The mobile app initializes Firebase from the installed platform configuration. Web needs the generated `firebase_options.dart` supplied to `Firebase.initializeApp`.
